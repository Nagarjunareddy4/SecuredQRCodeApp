THE FLOW

        
Private by design, simple to use.

        
SecureQR is useful for short-lived, person-to-person transfers when email attachments, cloud storage or messaging uploads are not appropriate.

      

      

        
01
Derive
Your password is turned into an encryption key using a unique random salt and PBKDF2.

        
02
Encrypt
Your message is encrypted locally with AES-256-GCM before a QR payload is created.

        
03
Transfer
The encrypted message is transferred through a QR code without uploading the original content.

        
04
Unlock
The recipient scans or pastes the payload, enters the password, and decrypts locally.

COMMON QUESTIONS

        
Frequently asked questions.

      

      

        
Does SecureQR upload my message or file?
No. Encryption happens in your browser. SecureQR does not need your plaintext data, password or account.

        
Can I transfer files?
File transfer is marked Coming soon. The current release focuses on secure private-message transfers while a faster large-file transfer method is being prepared.

        
What happens when I scan a SecureQR code with another scanner?
The scanner sees a SecureQR link or encrypted payload, never the original message or file. Opening the SecureQR link loads the encrypted data into this application and asks for the password before anything can be decrypted. A random scanner cannot be forced to show its own password box because QR codes do not control other apps.

        
Why do large files use multiple QR codes?
A QR code has limited storage capacity. SecureQR encrypts the complete file first, then divides the encrypted result into numbered parts for reconstruction.

        
What happens if a QR part is missing?
The file cannot be unlocked until every part has been scanned or pasted. The unlock screen reports missing or duplicate parts.

        
Is SecureQR permanent storage?
No. SecureQR is designed for temporary private-message transfers, not long-term storage.

      

    


    

      

        

          
SECURITY MODEL

          
Designed to minimize what the website needs to know.

          
There is no account requirement, no upload endpoint, and no server-side decryption in this prototype. The browser uses the Web Crypto API for password-based key derivation and AES-GCM encryption.

        

        

          
✓
Random salt
Each encryption operation gets a fresh salt.

          
✓
Authenticated encryption
AES-GCM detects tampering and wrong passwords.

          
✓
Versioned payloads
New formats can evolve without silently breaking older codes.

          
!
QR is not a vault
Anyone can photograph a QR. The password is what protects the encrypted content.
